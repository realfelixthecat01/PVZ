# PVZ: «Пункт Выдачи Задачек»

Учебный программный комплекс для проверочных работ: учитель собирает задачник, ученик выполняет его за компьютером, результаты и файлы возвращаются учителю. Комплекс состоит из двух настольных приложений для Windows (.NET 10) и серверной части на Node.js, развёрнутой на Vercel.

Авторы: Козыро Ярослав Дмитриевич и Захарик Тимур Александрович, 9 «А» класс, ГУО «Колодищанская средняя школа № 2», агрогородок Колодищи, Минский район.

## Что в репозитории

| Папка | Назначение |
| --- | --- |
| `PVZ.Core` | Общая библиотека: модель задачника, формат `.pvz`, подсчёт баллов, запуск Python и PascalABC.NET, клиент онлайн-сессий |
| `PVZT` | Приложение учителя: редактор задачников, каталог, онлайн-сессии, наблюдение за экранами учеников |
| `PVZP` | Приложение ученика: прохождение задач с кодом, пропусков, выбора ответа, соответствий и коротких ответов, отправка прогресса и файлов |
| `PVZ.Catalog`, `PVZ.CatalogSeed` | 70 готовых наборов заданий (математика с 1 класса, английский со 2, информатика с 6) и утилита их сборки |
| `pvz-server` | Сервер и сайт: Express, аккаунты, каталог, загрузки, онлайн-сессии |
| `PVZS.Tests` | Интеграционные проверки клиента против локально запущенного сервера |
| `docs` | Итоговый PDF проектной работы для подачи |
| `tools/pdf` | Текст проектной работы и сборка PDF |

## Как проходит работа

1. Учитель в PVZT собирает задачник и выбирает, как его передать: файл `.pvz`, один `.exe` с задачником внутри (ученику тогда не нужен установленный PVZP) или загрузка на сервер.
2. Задачник публикуется на сервере. Сервер выдаёт ученику шестизначный код, а учитель получает ссылку на сессию.
3. Ученик в PVZP вводит код, выполняет задания; после каждой задачи прогресс уходит на сервер. Файлы с решениями можно приложить прямо из программы.
4. Учитель видит список подключившихся, их баллы и, по желанию, снимки экрана. Результаты можно выгрузить в CSV или открыть сводку по каждому заданию: сколько учеников его решили, сколько решают частично и средний балл. Сессию можно продлить или закрыть.

Без интернета задачник открывается локально: сервер нужен только для онлайн-сессии, каталога и обмена файлами.

## Формат .pvz

Один файл: сигнатура `PVZPKG1`, длина JSON (int32, little-endian), SHA-256 от JSON и сам JSON, сжатый Brotli. Контрольная сумма позволяет заметить повреждение файла до разбора, а сжатие уменьшает размер в несколько раз. Внутри задачи пяти видов: с кодом и тестами, с пропусками «_», с выбором ответа, на соответствие и с коротким ответом. Лимит на размер файла: 16 МиБ.

Вариант «одним .exe» устроен проще: к обычному `PVZP.exe` дописывается блок `PVZTBK1`, длина и JSON задачника. При запуске приложение читает свой же файл, находит этот блок и открывает задачник; если блок не найден, это обычное приложение ученика.

## Сервер

`pvz-server` это обычное приложение Express, которое одинаково работает локально и на Vercel:

- состояние (аккаунты, сессии, индексы) хранится в Redis, а если Redis недоступен, то в JSON-файле `data/store.json`;
- файлы лежат в Vercel Blob, а локально это папка `data/blobs`;
- крупные файлы не проходят через функцию Vercel: сервер выдаёт временную ссылку, клиент загружает байты напрямую в Blob, после чего сервер проверяет размер и регистрирует файл;
- раз в сутки cron удаляет просроченные сессии, файлы и незавершённые загрузки;
- пароль администратора берётся из переменной окружения `PVZ_ROOT_PASSWORD`, встроенного пароля в коде нет;
- неудачные попытки входа считаются по адресу и имени аккаунта: после нескольких ошибок адрес временно не пускают дальше, плюс каждый маршрут имеет свой лимит запросов в минуту;
- ответы содержат `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` и `Content-Security-Policy` для страниц, `x-powered-by` отключён.

Сайт (главная, вход, регистрация, личный кабинет и админка) отдаётся тем же приложением из `public/` и `lib/pages/`. В кабинете учителя у каждого задачника есть кнопки «Результаты (CSV)» и «Статистика». Всё в комплексе работает бесплатно: покупки, подписки и ключи активации из проекта убраны, каталог и все сроки хранения открыты каждому учителю.

Ограничения: задачник до 16 МиБ, файл обмена до 32 МиБ, весь обмен в сессии до 512 МиБ, кадр экрана до 2 МиБ. Срок хранения учитель выбирает сам при публикации: 48 часов, неделя, две недели (по умолчанию), месяц, год или постоянное хранение. Гостевой режим без аккаунта живёт 48 часов и вмещает один задачник.

## Локальный запуск

Нужен Node.js 22 или новее.

```bash
cd pvz-server
npm install
npm start
```

Сервер слушает `http://localhost:1729`. При первом запуске создаётся корневая учётная запись `admin@pvz.local`. Если переменная `PVZ_ROOT_PASSWORD` не задана, сервер сам генерирует пароль и печатает его в консоль; для боевого сервера пароль задают в настройках окружения.

Наполнение каталога и раздела загрузок:

```bash
npm run seed -- --catalog ../zadachniki
npm run seed -- --downloads ../downloads
```

Для уже развёрнутого сервера есть `scripts/seed-remote.mjs`: он входит под корневой учётной записью, получает временные ссылки и загружает файлы в облако.

## Сборка приложений

Нужен .NET 10 SDK; версия зафиксирована в `global.json`, общие правила форматирования лежат в `.editorconfig`.

```bash
dotnet build PVZ.slnx
dotnet publish PVZT/PVZT.csproj -c Release -r win-x64
```

`PVZT` публикуется одним exe и вкладывает внутрь себя `PVZP.exe`: редактор берёт его как шаблон, когда учитель выбирает передачу задачника одним файлом.

## Проверки

```bash
dotnet run --project PVZS.Tests
```

Скрипт поднимает `pvz-server` на свободном порту с временными данными и проверяет вход, публикацию задачников, онлайн-сессию, прогресс, обмен файлами, статистику и CSV, каталог и скачивание сборок, регистрацию учителя и ученика, гостевой режим, историю результатов ученика и подсчёт баллов у новых типов заданий. Второй экземпляр сервера запускается с жёсткими настройками и проверяет блокировку после неудачных входов, лимиты запросов, размеры пакетов и файлов, выход за папку каталога, кривой JSON и изоляцию двух учителей. Последняя строка вывода печатает число проверок, сейчас их 130; пять проверок сборки `.exe` пропускаются, если рядом нет собранного `PVZP.exe`.

То же самое GitHub Actions прогоняет на каждый push и pull request в `.github/workflows/ci.yml`: сборка решения на Windows, интеграционные тесты, `node --check` для серверных модулей и проверка копирайта в каждом исходнике.
