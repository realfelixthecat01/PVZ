# ВВЕДЕНИЕ

**Постановка задачи.** Контрольные в нашем кабинете информатики чаще пишут на бумаге: учитель готовит варианты, раздаёт листы, потом переносит ответы в журнал руками. Когда класс садится за компьютеры, решения собирают по флешкам, баллы считают вручную. Мы хотели иначе: учитель один раз собирает задачник, ученик открывает его у себя, ответы проверяет программа, а результат сам уходит учителю. Характеристику учащегося выдают по порядку из постановления Министерства образования № 58 [2].

**Актуальность.** Компьютерный класс в школе есть, а общей среды для проверочных работ нет, и каждый учитель выкручивается как может. Онлайн-сервисы требуют постоянного интернета и аккаунт на каждого ученика, задачи по программированию проверяют плохо, задачник одним файлом не хранят. Арендовать сервер ради нескольких уроков в неделю школа не может. Отсюда наши требования: работать и без сети, и с ней, а серверной части обходиться бесплатным размещением.

**Краткий обзор.** Мы посмотрели, чем уже пользуются, и выбрали архитектуру: настольные приложения запускают код на машине ученика, а лёгкий сервер отвечает за раздачу и наблюдение. По дороге разобрались с документацией .NET [8], Node.js [6], Redis [9], Vercel Blob [7], JSON [3], HTTP [5] и Brotli [4], а саму работу оформили по ГОСТ 7.1-2003 [10].

**Цель работы.** Сделать программный комплекс «Пункт Выдачи Задачек» (PVZ): конструктор задачников для учителя и проигрыватель для ученика, чтобы готовить, выполнять и проверять задания автоматически, не оплачивая аренду сервера.

**Задачи:**

- придумать формат файла задачника для передачи от учителя ученику;
- собрать приложение учителя: редактор, каталог, онлайн-сессии;
- собрать приложение ученика: тесты, пропуски, варианты, запуск программ;
- написать сервер: аккаунты, каталог, файлы, экран ученика;
- перенести серверную часть на бессерверную платформу;
- проверить комплекс автоматическими проверками.

**Гипотезы.** Мы предполагали три вещи. Что одного файла с контрольной суммой и сжатием хватит для передачи задачника без базы данных, а повреждение видно сразу. Что серверную часть можно перенести на бессерверную платформу без потери функций и платить за неё меньше, чем за виртуальный сервер. И что при проверке ответов на компьютере ученика, а на сервере только прогресса, работа не оборвётся из-за пропажи интернета.

# ГЛАВА 1. ПОСТАНОВКА ЗАДАЧИ

## 1.1. Предметная область

На уроках информатики и кружках учителю нужен набор задач с автоматической проверкой: ученик пишет программу, система запускает её на тестах и выставляет баллы. Для себя мы решили, что задачник это три вещи сразу: условие, среда для кода и тесты. У каждой задачи есть условие, входные и выходные данные, ограничение по времени и максимальный балл. Учитель собирает набор в файл `.pvz`, ученик открывает его и решает, а программа считает результат.

Ролей две: учитель редактирует задачи и публикует задачник, ученик проходит его по файлу или короткому коду. Объект исследования: автоматическая проверка учебных заданий. Предмет: архитектура настольных приложений и серверного API PVZ.

## 1.2. Аналоги

Сравнивали мы комплекс с тем, чем пользуются в школе. Электронный журнал удобен для отметок, но задания там выдаются текстом, а решения проверяют руками. Конструкторы тестов проверяют выбор варианта, но код не запустят. Moodle закрывает и тесты, и задания, однако требует сервера и человека, который его обслуживает. Олимпиадные сервисы проверяют код, но рассчитаны на соревнование и без интернета не работают. PVZ занял промежуточное место: проверяет программы на PascalABC.NET и Python, работает без сети, хранит задачник в одном файле и проводит занятие онлайн.

## 1.3. Назначение

Комплекс рассчитан на практикумы по программированию, контрольные в компьютерном классе, домашние задачники и мониторинг класса онлайн. Ученик остаётся в привычной среде Pascal и Python, а учитель получает единый набор заданий и автоматический подсчёт баллов. Электронный журнал комплекс не заменяет: развёрнутые ответы не проверяет и итоговые отметки не ставит.

# ГЛАВА 2. СРЕДСТВА РАЗРАБОТКИ

## 2.1. Выбор платформы

Настольные приложения сделаны на C# под .NET 10 с интерфейсом Windows Forms. В школьном классе обычные Windows-компьютеры, ставить на каждый веб-сервер никто не станет. WinForms даёт окно, которое запускается двойным щелчком, и позволяет запускать компиляторы прямо на машине ученика.

Сервер написан на Node.js с Express [6]: он одинаково работает локально и в облаке и не требует отдельной базы данных. Состояние хранится в Redis [9], файлы в Vercel Blob [7]; без внешних сервисов сервер переходит на локальный JSON-файл и диск. Форматы опираются на JSON [3] и HTTP [5], сжатие описано в RFC 7932 [4].

## 2.2. Структура проекта

Код разделён на общую библиотеку и два приложения. В `PVZ.Core` лежат модель задачника, чтение и запись `.pvz`, подсчёт баллов, запуск Python и PascalABC.NET и клиент онлайн-сессий. `PVZT` это приложение учителя, `PVZP` приложение ученика, `pvz-server` хранит аккаунты и сессии и раздаёт каталог, `PVZ.Catalog` держит наборы заданий, `PVZS.Tests` интеграционные проверки.

# ГЛАВА 3. РЕАЛИЗАЦИЯ

## 3.1. Формат файла задачника

Базу данных для раздач мы класть в школу не хотели, поэтому задачник переехал в один файл. Он начинается с сигнатуры `PVZPKG1`, дальше идут длина JSON (четыре байта, little-endian), контрольная сумма SHA-256 от JSON и сам JSON, сжатый Brotli [4]. Файл пишется во временный и только потом заменяет старый, иначе при сбое питания задачник остаётся наполовину записанным. При чтении проверяются размеры (не более 16 МиБ на пакет и 64 МиБ на документ), сигнатура и контрольная сумма: повреждённый файл отклоняется до разбора.

Внутри документа лежат предмет, класс, настройки показа и список задач. Задача бывает пяти видов: с кодом и тестами ввода и вывода, с пропусками, где ученик вписывает слова вместо подчёркиваний, с выбором ответа, на соответствие пар и с коротким ответом. У задачи есть цена в баллах и бонус за полное решение, а номер версии схемы (`schemaVersion`) позволяет менять формат, не ломая старые файлы. ZIP дал бы похожий размер, но пришлось бы разбирать имена и защищаться от выхода за пределы папки.

## 3.2. Приложение учителя

PVZT это рабочее место учителя. В редакторе задаются предмет и класс, тексты задач, тесты с входом и выходом, пропуски и варианты ответа, пары соответствий, короткие ответы, баллы и бонусы. Отдельно настраивается поведение плеера: последовательная разблокировка задач, окно поверх остальных, полный экран, отключение проводника и разрешённые компиляторы. Задачник можно закрыть паролем учителя, он хранится как результат PBKDF2 с солью.

Каталог загружается с сервера по предмету и классу и показывает готовые задачники с размерами. В онлайн-разделе можно опубликовать файл, получить шестизначный код для учеников, следить за подключившимися, видеть баллы и снимки экрана, продлевать и закрывать сессию, скачивать присланные работы. Публикация требует аккаунт учителя (имя и пароль) или гостевой режим без регистрации: один задачник на 48 часов. Срок хранения выбирает сам учитель при публикации: от 48 часов до постоянного. У задачника есть «Статистика»: сколько учеников решили каждую задачу и какой средний балл, а таблица результатов выгружается в CSV для журнала.

Нам надоело объяснять классу, куда класть две программы, поэтому задачник передаётся тремя способами: файл `.pvz` для класса с установленным PVZP, один `.exe` с задачами внутри и публикация на сервере, где класс подключается по коду. Для второго способа редактор берёт приложение ученика как шаблон и дописывает задачник в конец файла. Сборка PVZT тоже делается одним exe и вкладывает внутрь PVZP.exe, который извлекается во временную папку при запуске.

## 3.3. Приложение ученика

Ученик запускает PVZP, вводит код сессии, имя, фамилию и класс. Код учитель диктует вслух, а имя нужно, чтобы в отчёте было видно, чья это работа. Аккаунт ученика, те же поля плюс пароль, подставит данные сам и сохранит результаты по всем задачникам. Дальше он видит список задач и выполняет их по очереди или в свободном порядке, если последовательную разблокировку не включали. Тесты проверяются сравнением вывода программы с эталонным, пропуски сравнением введённых слов с вариантами, а выбор ответа, соответствие и короткий ответ сверяются без запуска программ. Баллы начисляются сразу, бонус только если задача решена полностью.

Проверку ответов мы оставили на компьютере ученика: сервер не хранит чужой код и ничего на нём не запускает. Программы на Python и PascalABC.NET идут через установленные интерпретаторы, время выполнения ограничено, чтобы задача не зависла. Прогресс сохраняется локально после каждого действия и уходит на сервер, когда связь есть: пропала сеть, ученик продолжает, а при восстановлении очередь уходит повторно.

## 3.4. Сервер и сайт

Один и тот же код на Node.js обслуживает API и сайт: главную страницу, вход и регистрацию, личный кабинет и админку. Состояние лежит в Redis [9], а без переменной `REDIS_URL` в локальном JSON-файле, файлы в Vercel Blob [7] или на диске.

Аккаунты учителей и учеников защищены паролем с PBKDF2 (100 000 итераций, SHA-256), вход идёт по имени и фамилии, а гость хранит в приложении секретный ключ. После входа сервер выдаёт токен доступа на 12 часов, а веб-кабинет на 30 дней. Срок хранения выбирает учитель: 48 часов, неделя, две недели обычно, месяц, год или постоянное хранение. Гостевой задачник живёт 48 часов, просроченные записи и файлы удаляет ежедневная задача cron.

Защиту держим в нескольких местах. Пароль администратора задаётся переменной окружения, в коде постоянного пароля нет; без него сервер генерирует случайный и печатает его в консоль. Неудачные входы считаются по адресу и имени аккаунта и приводят к временной блокировке, а у каждого маршрута есть свой предел запросов в минуту. Ответы содержат заголовки `X-Content-Type-Options`, `X-Frame-Options` и `Content-Security-Policy`, а файлы из Blob наружу идут только через сервер после проверки прав: чужой учитель не получит ни чужой задачник, ни его результаты.

Крупные файлы через функцию Vercel не проходят, тело запроса ограничено 4,5 МБ. Поэтому сервер выдаёт клиенту временную ссылку на загрузку в Blob, клиент отправляет байты напрямую, а сервер потом проверяет размер и регистрирует файл. Ограничения заданы в одном месте: задачник 16 МиБ, файл обмена 32 МиБ, кадр экрана 2 МиБ. По сессии сервер считает сводку: `/stats` по задачам, `/export.csv` таблицу с BOM и разделителем `;`, чтобы кириллица открылась в Excel.

## 3.5. Переход с арендованного сервера на Vercel

Раньше серверная часть жила на арендованном виртуальном сервере: платили весь год, а нагружали пару уроков в неделю. Мы перенесли сервер на Vercel: код собирается из репозитория, состояние в Redis, файлы в приватном хранилище Blob, адрес проекта постоянный. Старый сервер на C# удалён, данные начаты заново. Вместо передачи больших файлов через функцию мы перешли на временные ссылки, а уборку данных сдвинули на ночь, потому что бесплатный план хостинга запускает cron раз в сутки.

## 3.6. Правовая защита

Исходный код, приложения, формат `.pvz` и документация принадлежат авторам. В репозитории лежит проприетарная лицензия: изучать код можно, скачивать и запускать программу для себя и без коммерции тоже, как и демонстрировать её на учебных мероприятиях с указанием авторов. Копировать, распространять, менять и использовать в коммерческих целях без письменного согласия нельзя, а подача работы на конкурс исключительные права организаторам или школе не передаёт. Опираемся на Закон Республики Беларусь «Об авторском праве и смежных правах» [1]: исключительное право возникает в силу факта создания и не требует регистрации. Строка с авторами и годом стоит в начале каждого исходного файла, перечень сторонних библиотек собран в `NOTICE`.

# ГЛАВА 4. ТЕСТИРОВАНИЕ

Проверять руками каждый сценарий после правки долго, поэтому мы превратили их в автоматические проверки. Проект `PVZS.Tests` поднимает сервер локально и проходит те же шаги, которыми пользуются приложения: вход учителя, публикация задачника, подключение ученика по коду, прогресс, обмен файлами, кадр экрана, статистика по заданиям и выгрузка CSV, продление и закрытие сессии, каталог и скачивание сборок. Отдельно проверяются регистрация, гостевой режим и история результатов ученика. Сборка задачника в один `.exe` тоже проверяется: файл создаётся и читается обратно.

Второй экземпляр сервера поднимается с жёсткими настройками и проверяет защиту: блокировку адреса после трёх неудачных входов, предел запросов в минуту, отказ на пакете тяжелее 16 МиБ, файле тяжелее 32 МиБ и кадре тяжелее 2 МиБ, кривой JSON, сверхдлинное имя ученика, выход за папку каталога через `../` и доступ одного учителя к чужому задачнику. Отдельно проверяются подсчёт баллов и онлайн-прогресс у новых типов заданий. Всего в наборе 130 проверок, и все они проходят.

После переноса на Vercel те же сценарии мы прогнали по настоящему адресу: страницы сайта, каталог, скачивание сборок, публикацию задачника и отказ cron без секрета. Теперь такую проверку на каждую отправку делает GitHub Actions: собирает решение, прогоняет тесты, смотрит синтаксис серверных модулей и наличие копирайта в исходниках.

# ГЛАВА 5. ПРИМЕНЕНИЕ

Пользоваться комплексом можно в четырёх ситуациях. На уроке учитель раздаёт файл `.pvz`, и класс работает без интернета. На контрольной он публикует задачник и следит за классом онлайн. Дома ученик решает в своём темпе, а на олимпиадной тренировке учитель включает последовательную разблокировку.

Нужны компьютеры с Windows и установленные Python и PascalABC.NET; серверная часть уже развёрнута, школе ничего администрировать не нужно. Пропал интернет, занятие продолжается по локальному файлу, а результаты дождутся связи.

# ЗАКЛЮЧЕНИЕ

Работа закончена: сделан комплекс PVZ. В него вошли формат задачника `.pvz`, приложение учителя PVZT, приложение ученика PVZP, общая библиотека, сервер с сайтом и каталог из 70 бесплатных задачников. Серверную часть перенесли с арендованного виртуального сервера на Vercel, старый сервер убрали. Комплекс прошёл 130 автоматических проверок локально, а после переноса те же сценарии проверили по боевому адресу.

Теперь про гипотезы. Первую удалось подтвердить: один файл с сигнатурой, контрольной суммой и сжатием переносит задачник без базы данных, а повреждение видно ещё до разбора. Вторая подтвердилась частично: перенос на бессерверную платформу сохранил все функции и убрал плату за аренду, но загрузку файлов и уборку данных пришлось переделать. Третья подтвердилась: проверка ответов на компьютере ученика даёт работу без постоянной связи, а передача прогресса показывает учителю актуальную картину.

Новизна, на наш взгляд, в сочетании, которое в школьных проектах редкое: свой двоичный формат с контрольной суммой, настольные приложения с запуском кода на месте ученика, бессерверный сервер и единый каталог заданий. Теоретически работа описывает, как разделить проверку между клиентом и сервером, практически это готовый инструмент, который не требует затрат на инфраструктуру.

Дальше хотим клиент для Linux, защиту от списывания, импорт заданий из других форматов, передачу итогов в электронный журнал и регистрацию программы в Национальном центре интеллектуальной собственности.

# ПРИЛОЖЕНИЕ А

| Смещение | Размер | Содержимое |
| --- | --- | --- |
| 0 | 7 байт | сигнатура `PVZPKG1` |
| 7 | 4 байта | длина JSON, little-endian |

Внутри `.exe` к `PVZP.exe` дописаны `PVZTBK1` и сам JSON. Каталог и сборки отдают `GET /api/catalog/:subject/:classNumber` и `GET /api/downloads`.

| Метод и адрес | Назначение |
| --- | --- |
| `POST /api/teacher/login` | вход учителя |
| `POST /api/account/register`, `login`, `/api/guest/login` | аккаунт учителя или ученика, вход гостя |
| `GET /api/student/history` | результаты ученика по всем задачникам |
| `POST /api/upload/begin`, `complete` | публикация задачника и файлов |
| `POST /api/taskbooks/:token/sessions` | подключение ученика по коду |
| `PUT /api/student/sessions/:id/progress` | баллы и отметки о выполнении |
| `GET /api/admin/students/:ssid/watch/frame` | кадр экрана ученика |
| `GET /api/teacher/sessions/:id/stats`, `export.csv` | сводка по задачам, таблица для Excel |
