# PVZS — сервер Пункта Выдачи Задачек

`PVZS` — единственный сервер системы. Он работает на **домашнем Windows-сервере, который включён 24/7**, компилируется в один самодостаточный `PVZS.exe` и поднимается как служба Windows. PVZS хранит все .pvz задачники, ведёт аккаунты, квоты и подписки в файловой SQLite-базе, отдаёт публичный сайт (главная, тарифы, вход, регистрация, кабинет учителя) и таблицу администратора на `/admin`. Все данные лежат в папках **рядом с exe** — отдельная БД или установщик не нужны.

Учитель и ученик работают только через десктопные клиенты **PVZT** и **PVZP**; они сами узнают адрес по постоянному `https://pvz.k11.by` (переопределяется переменной `PVZ_SERVER_URL`). Никаких локальных серверов, туннелей и внешних реестров у клиентов нет.

```
PVZS.exe
sessions\               ← создаётся при первом запуске
    pvz.db              — SQLite: аккаунты, токены, ключи активации, подписки
    <32-char hex id>\   — папка одного онлайн-задачника
        taskbook.pvz
        session.json    — хеш токена, ученики, метаданные пересылки файлов
        files\          — пересылаемые файлы: материалы учителя и работы учеников
zadachniki\             ← каталог готовых задачников (опционально, создаётся вручную)
    english\6\
    math\9\
```

## Публикация exe

`dotnet build PVZ.sln -c Debug` даёт обычную быструю сборку для разработчика; самодостаточный одиночный файл получается только при publish:

```powershell
dotnet publish PVZS\PVZS.csproj -c Release -r win-x64
```

Получается `PVZS.exe` (один файл, ~52 МБ, работает на машинах без .NET). Так же для 32-битной Windows: `-r win-x86`. `PVZS.csproj` уже содержит `PublishSelfContained`/`PublishSingleFile`, поэтому одиночный exe создаётся автоматически.

По умолчанию `PVZS.exe` слушает **только `http://127.0.0.1:1729`** — в интернет напрямую никто не ходит, HTTPS отдаёт Caddy (см. «Установка»). Адрес можно переопределить переменной `ASPNETCORE_URLS`.

## Одиночный exe «Сервер и ссылка» (Cloudflare)

Самый простой способ поднять сервер и получить публичную ссылку — приложение **PVZLauncher**. Оно не требует проброса портов на роутере: соединение туннеля исходящее.

```powershell
dotnet publish PVZLauncher\PVZLauncher.csproj -c Release -r win-x64
# → PVZLauncher\bin\Release\net10.0-windows\win-x64\publish\PVZLauncher.exe
```

Получается **один exe**. При первом запуске он:

- распаковывает вшитый сервер в папку `server\PVZS.exe` рядом с собой;
- создаёт рядом папки `sessions\` (аккаунты `pvz.db`, онлайн-задачники и работы учеников) и `zadachniki\` (каталог готовых задачников) — данные всегда лежат рядом с exe;
- запускает сервер на `http://127.0.0.1:1729` и туннель, показывает ссылку (кнопки «Копировать» и «Открыть»).

Флаг `PVZLauncher.exe --start` сразу поднимает сервер, не требуя нажатия кнопки. Закрытие окна останавливает сервер и туннель.

Туннели (любой из них не требует открывать порты на роутере):

1. **Постоянная ссылка.** Положите рядом с exe файл `cloudflared-token.txt`: первая строка — токен туннеля Cloudflare (Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared), вторая (необязательная) — постоянный https-адрес туннеля, который покажет лаунчер. Если вторая строка пуста, допишите адрес, иначе лаунчер не сможет его показать.
2. **Быстрая ссылка.** Без файла: cloudflared выдаёт случайный `https://…trycloudflare.com` при каждом запуске.
3. **Запасной localhost.run.** Если сеть блокирует `api.trycloudflare.com` (в логе туннель Cloudflare не дал ссылку), лаунчер сам поднимает туннель через `ssh -R` на localhost.run и показывает `https://….lhr.life`.

Ссылку ученик вставляет в PVZP (поле «Адрес сервера» при входе), учитель — в диалог адреса сервера в меню PVZT. Пока поле пустое, клиенты используют `https://pvz.k11.by`.


## Данные и их расположение

По умолчанию всё хранится относительно папки exe (`AppContext.BaseDirectory`):

| Путь | Содержимое | Переопределение |
| --- | --- | --- |
| `sessions\` | папки онлайн-сессий и `pvz.db` | `PVZ_SERVER_DATA_DIR` |
| `sessions\pvz.db` | SQLite: аккаунты, токены, ключи, подписки | `PVZ_SERVER_DB_PATH` |
| `zadachniki\` | каталог готовых задачников `<subject>\<class>\*.pvz` | `PVZ_TASKBOOK_CATALOG_DIR` |
| `downloads\` | сборки `PVZP.exe`, `PVZT.exe`, `PVZS.exe` для скачивания с сайта | `PVZ_DOWNLOAD_DIR` |

Для резервной копии достаточно скопировать всю папку `sessions\` — там аккаунты, подписки и онлайн-задачники. На одном каталоге данных работает один процесс (SQLite рассчитан на один экземпляр, не на кластер).

При запуске сервер сам наполняет каталог стандартными задачниками (английский 25 + математика 31 по классам, плюс пустые шаблоны информатики для 6–11 классов — 6 файлов) в `zadachniki\`, если их там ещё нет; существующие файлы не перезаписываются. Отключается переменной `PVZ_AUTO_SEED_CATALOG=0`. Наполнить вручную: `dotnet run --project PVZ.CatalogSeed` (перезаписывает существующие) или `PVZ.CatalogSeed.exe <папка>`.

## Аккаунты и права

Учителя регистрируются на `/register` (**имя аккаунта, ФИО, школа/гимназия, email, пароль**); всё хранится в `pvz.db`. Имя аккаунта — логин (3–32 символа: латиница, цифры, `.`, `-`, `_`); с ним можно входить на `/login` и `/admin`, email тоже работает как логин. Пароли хешируются PBKDF2 (100 000 итераций, SHA-256, своя соль на пользователя) и в открытом виде нигде не хранятся. Вход выдаёт bearer-токен из 43 символов; в SQLite хранится только SHA-256-хеш, токены **переживают перезапуск сервера** до истечения. Каждый `/api/account/*` требует `Authorization: Bearer <токен>`; файлы кабинета приватные — чужой или несуществующий id отдаёт 404.

Общий пароль учителя `ezfridgembxd` по-прежнему работает в десктопных приложениях и как пароль встроенного администратора: `POST /api/teacher/login` проверяет его на сервере (сравнение за постоянное время) и возвращает обычный токен аккаунта администратора `admin` (`admin@pvz.local`). Таблица `/admin` открывается этими же учётными данными. Администратор видит учителей, их активные сессии и генерирует ключи активации (`POST /api/admin/keys`); обычные аккаунты получают `403 Доступ только для администратора`. Запросы с других машин обязаны идти по HTTPS — TLS терминирует Caddy перед сервером.

## Тарифы и сроки хранения

У каждого аккаунта учителя есть план с лимитами по сроку хранения. Срок выбирается **для каждого загруженного файла** в кабинете; по истечении таймера сервер удаляет файл сам (фоновая уборка каждые 30 минут плюс ленивая уборка при каждом действии):

| Срок | Бесплатный | Pro | Pro+ |
| --- | --- | --- | --- |
| 48 часов | 5 | 20 | без лимита |
| 1 неделя | — | 15 | без лимита |
| 1 месяц | — | 5 | без лимита |
| 1 год | — | 1 | 100 |
| навсегда | — | — | 20 |

Загрузка сверх плана возвращает понятную ошибку («Срок хранения … недоступен на тарифе …»). Кабинет показывает все облачные файлы с живым отсчётом до удаления, позволяет скачать их владельцу, удалить сразу и показывает план и занятость. Аккаунт администратора без лимитов.

## Ключи активации и подписки

Все платежи офлайн: администратор в `/admin` генерирует ключи (вид **storage / subject / class / all** — план `pro`/`pro_plus`, подписка на предмет, предмет+класс или весь каталог; срок 1–3650 дней, по умолчанию 30). Ключ имеет вид `PVZ-XXXX-XXXX-XXXX`; учитель вводит его в кабинете (`POST /api/account/keys`), и план/подписка активируются сразу.

- **Подписка на класс** (предмет + класс), **на предмет** (все классы предмета) и **на все предметы** (весь каталог) дают доступ к скачиванию из каталога на свой срок.
- Список каталога (`GET /api/catalog/{subject}/{classNumber}`) открыт, но скачивание требует входа (аноним → 401) и активной подписки (нет подписки → 403 «Нужна подписка на предмет, класс или весь каталог»).
- Коды ключей хранятся хешированными; таблица показывает код один раз при генерации, дальше только метаданные.

## Сайт

Сервер сам отдаёт весь публичный сайт (по умолчанию по-русски):

- `/` — главная с анимацией появления при загрузке и скролле, блок «Скачать приложения» с кнопками PVZT и PVZP (когда сборки выложены).
- `/pricing` — тарифы хранения, три месячных подписки и FAQ.
- `/login`, `/register` — вход и регистрация учителя.
- `/cabinet` — профиль, смена пароля, форма ключа активации, облачные файлы с отсчётом удаления, загрузка, список подписок каталога.
- `/admin` — таблица администратора: все учителя с планами и активными сессиями, онлайн-сессии с «Продлить», «Закрыть», «Скачать», живой прогресс учеников, генератор ключей, карточка «Сборки приложений» (PVZP, PVZT и сам PVZS) и карточка «Сервер и обновление» (версия и пути, запуск `.exe`, обновление по URL).

В шапке — переключатель **RU/EN** и валют **BYN/USD/RUB** с пересчётом цен (база USD; BYN 3.25 и RUB 95 за доллар; язык и валюта сохраняются в `localStorage`).

## Скачивание приложений (PVZP, PVZT, PVZS)

Клиенты и сервер раздаются тем же узлом, что и сайт, из папки `downloads\` рядом с `PVZS.exe` (переопределяется переменной `PVZ_DOWNLOAD_DIR`). Положите туда `PVZP.exe` и `PVZT.exe` — на главной появятся кнопки скачивания; если файла нет, карточка показывает «Скоро».

- `GET /api/downloads` — публичный список клиентов (id, имя файла, роль, размер, доступность).
- `GET /downloads/{id}` — сам файл; публично отдаются только `pvzp` и `pvzt` (сервер → 404), поддерживается докачка по range.
- `GET /api/admin/downloads` и `GET /api/admin/downloads/{id}` — то же плюс `pvzs`, но только администратору (нужен bearer-токен, без него → 401, обычному учителю → 403).

Отдельно выкладывать `PVZS.exe` не обязательно: если файла `downloads\PVZS.exe` нет, администратору отдаётся **запущенный** сервер (published single-file `PVZS.exe`). При запуске через `dotnet PVZS.dll` сервер недоступен для скачивания — в разработке это ожидаемо.

## Установка на серверный ПК (Program Files)

На серверном Windows-ПК просто запустите `PVZLauncher.exe` (один файл). Лаунчер запросит права администратора (манифест `requireAdministrator`) и сам разложит всё в `C:\Program Files (x86)\PVZ`:

- `PVZS.exe` — сервер (single-file) в корне папки;
- `PVZP.exe`, `PVZT.exe` — клиенты в `downloads\` (их раздаёт сайт);
- `sessions\`, `zadachniki\`, `downloads\` — данные, каталог и сборки рядом с сервером;
- служба Windows **PVZS** (автозапуск) — сервер работает постоянно, даже когда окно лаунчера закрыто;
- лаунчер копирует сам себя в `C:\Program Files (x86)\PVZ\PVZLauncher.exe` и перезапускается оттуда с `--start` (поднимает туннель Cloudflare и показывает ссылку).

Данные лежат в `Program Files`, поэтому запись в `sessions\`/`zadachniki\`/`downloads\` идёт от администратора — служба и лаунчер стартуют с повышенными правами. Отладка без установки: `PVZLauncher.exe --no-install` (или `PVZ_SKIP_INSTALL=1`).

## Онлайн-сессии и токены учеников

Публикация задачника (`POST /api/teacher/sessions` из PVZT) создаёт свою папку `sessions\<32-char hex id>\` с `taskbook.pvz` и `session.json` (хеш токена, подсказка токена, времена загрузки/истечения, владелец, записи учеников). Сессия живёт ровно 2 недели; «Продлить» сдвигает истечение ещё на 2 недели, «Закрыть» удаляет папку сразу, истёкшие сессии убираются автоматически. Администратор видит сессии всех учителей с именем владельца; обычный учитель — только свои.

Токены учеников — шесть символов из `A–Z` и `2–9` (например `P67VZ7`). Сервер хранит только хеши и короткую подсказку (`AB****`), полный токен невосстановим. Записи учеников — JSON на диске **без сквозного шифрования**; баллы сообщает клиент ученика и от подделки защищены слабо. Пакеты сжаты и проверяются по контрольной сумме, но **не шифруются** — шифрование не внедрялось, так как нет отработанной схемы безопасной доставки ключа.

## Пересылка файлов между учителем и учениками

Каждая онлайн-сессия работает как общая папка: учитель раздаёт материалы, ученики шлют работы — файлы живут на сервере в `sessions\<id>\files\` рядом с `PVZS.exe`. Облако и платные сервисы не нужны; пересылаемые файлы истекают вместе с сессией и удаляются вместе с её папкой («Закрыть» — сразу, «Продлить» — отодвигает срок).

- **Материалы** — учитель грузит в окне онлайн-кабинета PVZT («Отправить файл…»); каждый ученик задачника видит файл во вкладке «Файлы» в PVZP и может скачать.
- **Работы** — ученики прикладывают файлы во вкладке «Файлы»; их видит только автор и учитель, и при загрузке фиксируется «Имя Фамилия (класс)». Учитель скачивает «Скачать выбранный» и может удалить любой файл («Удалить»).
- Лимиты: 32 МиБ на файл, 512 МиБ на сессию; один файл за запрос (multipart). Имена файлов очищаются на сервере, содержимое хранится как есть (только контроль целостности, не шифрование). Чужой ученик за чужой работой получает 404.

## Запуск в Docker (VPS)

Основной способ: сервер и HTTPS-прокси (Caddy) работают контейнерами на VPS — домашний роутер и проброс портов не нужны.

1. **DNS**: в панели управления `k11.by` создать A-запись `pvz` → IP VPS (получится домен `pvz.k11.by`).
2. На VPS с Docker Compose:
```bash
git clone <репозиторий> PVZ
cd PVZ
docker compose up -d --build
```
3. Проверить: открыть `https://pvz.k11.by` с другого устройства. Caddy сам получит сертификат Let's Encrypt; на файрволе VPS должны быть открыты порты **80** и **443**.

Файлы: `Dockerfile`, `docker-compose.yml`, `docker/Caddyfile`. Данные сервера (аккаунты, задачники, файлы) лежат в Docker-volume `pvz-data` — `docker compose down` их не трогает.

- Обновление: `git pull && docker compose up -d --build`.
- Логи: `docker compose logs -f pvzs`.
- Бэкап: `docker compose exec pvzs tar czf - -C /data . > pvz-backup.tar.gz`.

## Установка на домашний Windows-сервер (альтернатива)

Схема: `PVZS.exe` (служба, слушает только `127.0.0.1:1729`) + **Caddy** (служба, терминирует HTTPS для `pvz.k11.by`, бесплатные сертификаты Let's Encrypt с автопродлением) + **A-запись** `pvz.k11.by` в панели управления k11.by, указывающая на домашний IP компьютера.

На серверном (постоянно включённом) Windows-компьютере:

1. **k11.by** → в панели управления создать A-запись **`pvz`** (домен `pvz.k11.by`) на IP этого компьютера.
2. **Роутер**: пробросить порты **80** и **443** на IP этого компьютера.
3. От имени администратора запустить:
```powershell
powershell -ExecutionPolicy Bypass -File deploy\install-pvzs.ps1
```
Скрипт: публикует `PVZS.exe` в `C:\PVZS\server\`, создаёт службы **PVZS** и **PVZ-Caddy** (автозапуск), скачивает Caddy, копирует `deploy\Caddyfile`, открывает в брандмауэре порты 80/443, а также публикует клиенты `PVZP.exe` и `PVZT.exe` в `C:\PVZS\server\downloads` (их раздаёт сайт; админ-панель дополнительно отдаёт сам `PVZS.exe`).

4. Проверить: с телефона/другого компьютера открыть **`https://pvz.k11.by`** (главная страница), затем в PVZT и PVZP адрес уже стоит по умолчанию.

Обновление сервера = перезапустить `install-pvzs.ps1` (заново публикует и пересоздаёт службы; `sessions\` в папке сервера не трогается). Резервная копия = скопировать `C:\PVZS\server\sessions`. Если домен другой — поправить `deploy\Caddyfile` и константу `TaskbookOnlineClient.DefaultServerUrl` в `PVZ.Core`, пересобрать клиенты.

Безопасность: службы запускаются от LocalSystem, поэтому ограничьте доступ к папке `C:\PVZS\server` на уровне NTFS только системой и администраторами. Данные (пароли, работы учеников) передаются по HTTPS, но в полёте и на диске не шифруются — это компромисс школьного проекта.

### Лимиты запросов

Per-IP лимиты (HTTP 429): 5 входов по паролю учителя, 10 входов/регистраций аккаунтов и 120 запросов account-API в минуту, 90 teacher-API и 120 student-API в минуту. `PVZ_RATE_LIMIT_MULTIPLIER` (целое 1–1000, по умолчанию 1) умножает бюджеты account/teacher/student-API — полезен, когда весь класс сидит за одним школьным IP; лимиты входов не масштабируются. Брандмауэр наружу открывает только 80/443 (это делает install-скрипт).

## Готовые коллекции английского и математики

`PVZ.CatalogSeed` генерирует готовые наборы на заполнение пропусков («_») по английскому и математике и пишет их в каталог (`Documents\PVZ\zadachniki` по умолчанию):

```powershell
dotnet run --project PVZ.CatalogSeed\PVZ.CatalogSeed.csproj             # → Documents\PVZ\zadachniki\english\ и …\math\
dotnet run --project PVZ.CatalogSeed\PVZ.CatalogSeed.csproj -- D:\Catalog
```

Скопируйте сгенерированные папки `english\` и `math\` в `zadachniki\` сервера (рядом с exe) или укажите путь через `PVZ_TASKBOOK_CATALOG_DIR`. Пропуск стоит 10 баллов, полностью верная задача добавляет бонус 10. Допустимые варианты ответов (`doesn't|does not`, `0.5|0,5|1/2`) хранятся рядом с основным; генератор отказывается писать пакет, если число «_» не совпало с числом ответов.

- **Английский** (классы 3–11): по сборнику на грамматическую тему — To be, множественное число, времена (Present Simple/Continuous, Past Simple/Perfect, Present Perfect), Conditionals, Passive Voice, модальные глаголы, степени сравнения, артикли, предлоги, местоимения, неправильные глаголы, словообразование.
- **Математика** (классы 1–11): сложение и вычитание, таблица умножения, порядок действий, деление с остатком, дроби и проценты, уравнения, отрицательные числа, НОД и НОК, пропорции, степени и формулы сокращённого умножения, квадратные уравнения и корни, функции и графики, системы, прогрессии, тригонометрия, логарифмы и показательные уравнения, производная и интеграл, вероятность, текстовые задачи.

## Десктопные клиенты

В решении два отдельных приложения:

- **PVZT** (учитель): собирает задачник с тестами кода или упражнениями на пропуски («_»), публикует в интернет (возвращает шестисимвольный токен ученика и срок), показывает живой прогресс учеников, рассылает файлы и скачивает работы в том же окне онлайн-кабинета, мониторит все сессии на сервере, скачивает готовые задачники из каталога.
- **PVZP** (ученик): открывает офлайн-файлы `.pvz` (и встроенные), решает тесты кода или заполняет пропуски (проверка по всем принятым вариантам), подключается к онлайн-задачнику по токену (имя, фамилия, класс), обменивается файлами с учителем во вкладке «Файлы» и периодически передаёт прогресс, пока задачник открыт.

Клиенты по умолчанию подключаются к **`https://pvz.k11.by`** (константа `TaskbookOnlineClient.DefaultServerUrl`). Переопределить адрес — переменной `PVZ_SERVER_URL`. Учительское приложение при необходимости само спрашивает общий пароль доступа (проверку выполняет сервер). Ученик считается онлайн, пока раз в 30 секунд приходит heartbeat.

> **Временно:** пока постоянный адрес `pvz.k11.by` не подключён, ссылку на сервер нужно вводить вручную — в PVZT кнопкой **«5. Адрес сервера (ссылка для входа)»**, в PVZP — полем **«Адрес сервера»** на экране входа. Пока ссылка не задана, клиенты не подставляют адрес по умолчанию и просят её ввести. Чтобы вернуть автоподстановку `pvz.k11.by`, удалите поле `TaskbookOnlineClient.RequireExplicitServerUrl` и ветку с ним в `TryResolveServerUrl()` (плюс связанные проверки в диалогах — они подписаны «ВРЕМЕННО»).

При первом запуске приложение создаёт `Documents\PVZ\downloads` и `Documents\PVZ\projects` (и проверяет их при последующих). Скачанное из каталога по умолчанию падает в `downloads`; задачник, созданный учителем офлайн, и папки редактора используют `projects`.

### Одиночные exe десктопов

Каждое десктопное приложение собирается в один самодостаточный exe без установленного .NET (`dotnet build` остаётся обычной быстрой сборкой):

```powershell
dotnet publish PVZP\PVZP.csproj -c Release   # → PVZP\bin\Release\net10.0-windows\win-x64\publish\PVZP.exe
dotnet publish PVZT\PVZT.csproj -c Release   # → PVZT\bin\Release\net10.0-windows\win-x64\publish\PVZT.exe
```

При публикации PVZT внутри него автоматически зашивается PVZP как `PlayerTemplate\PVZP.exe`; при первом запуске шаблон распаковывается рядом, а офлайн-задачники учителя создаются добавлением задачника к копии шаблона. Для 32-битных машин — `-r win-x86` к обеим командам. Онлайн-загрузка учителя не требует шаблона — он нужен только функции «создать задачник exe» для офлайна.

## API

Страницы: `GET /` (главная), `/pricing`, `/login`, `/register`, `/cabinet`, `/admin`, `GET /health`.

Account API (bearer из `/api/account/login`):

- `POST /api/account/register` — имя аккаунта, ФИО, школа, email, пароль; возвращает токен и профиль.
- `POST /api/account/login`, `POST /api/account/logout` — токен-сессии (вход по имени аккаунта или email).
- `GET/PUT /api/account/me` — профиль (план, занятость, подписки) и правки профиля.
- `PUT /api/account/me/password` — смена пароля.
- `POST /api/account/keys` — активация ключа.
- `GET /api/account/files` — облачные файлы со сроками удаления.
- `POST /api/account/files` — загрузка `.pvz` с выбранным сроком хранения (проверка квоты).
- `GET /api/account/files/{id}/download` — скачивание только владельцем.
- `DELETE /api/account/files/{id}` — немедленное удаление облачного файла.

Скачивание приложений (публично: PVZP и PVZT; PVZS — только администратор):

- `GET /api/downloads` — доступные клиенты с именами файлов и размерами.
- `GET /downloads/{id}` — скачать клиент (`pvzp`/`pvzt`) с поддержкой докачки.
- `GET /api/admin/downloads` — все сборки, включая сервер (bearer администратора).
- `GET /api/admin/downloads/{id}` — скачать любую сборку, включая `pvzs` (bearer администратора).

Admin API (только администратор):

- `POST /api/admin/keys` — ключ активации (storage / subject / class / all).
- `GET /api/admin/keys` — сгенерированные ключи с метаданными.
- `GET /api/admin/teachers` — учителя с планом, истечением и активными сессиями.
- `GET /api/admin/server` — версия сервера, пути данных/каталога/сборок и размер каталога.
- `POST /api/admin/exec` — загрузить `.exe` (multipart `file` + `args`) и выполнить на сервере; возвращает код выхода и вывод.
- `POST /api/admin/exec-path` — выполнить уже лежащий на диске файл (`{path, args}`; путь относительно папки сервера).
- `POST /api/admin/update` — скачать файл по URL (проверка `sha256`) и при желании запустить (`{url, sha256, args, run}`).

> ⚠️ Запуск произвольного exe и обновление — это удалённое выполнение кода на серверном ПК: админ-токен равносилен доступу к машине. Держите его в секрете.

Teacher и catalog API:

- `POST /api/teacher/login` — проверка общего пароля, выдача bearer-токена.
- `POST /api/teacher/sessions` — загрузка `.pvz`; возвращает id сессии, шестисимвольный токен ученика и срок.
- `GET /api/teacher/sessions` — активные сессии с подсказкой токена, сроком и полным прогрессом учеников.
- `POST /api/teacher/sessions/{id}/extend` — продлить ещё на 2 недели.
- `DELETE /api/teacher/sessions/{id}` — закрыть сессию и удалить её папку.
- `GET /api/teacher/sessions/{id}/download` — скачать хранящийся пакет.
- `GET /api/catalog/{subject}/{classNumber}` — список `.pvz` каталога (открыто).
- `GET /api/catalog/{subject}/{classNumber}/{fileName}` — скачать пакет каталога (вход + подписка).
- `POST /api/taskbooks/{token}/sessions` — создать сессию ученика с анкетой.
- `PUT /api/student/sessions/{sessionId}/progress` — отчёт о баллах/прогрессе.
- `GET /api/student/sessions/{sessionId}/files` — материалы и свои работы ученика.
- `GET /api/student/sessions/{sessionId}/files/{fileId}` — скачать материал или свою работу (чужая → 404).
- `POST /api/student/sessions/{sessionId}/files` — загрузить работу (multipart, файл ≤ 32 МиБ).
- `GET /api/teacher/sessions/{id}/files` — все файлы сессии с именами учеников (bearer).
- `POST /api/teacher/sessions/{id}/files` — загрузить материал для всех учеников (bearer).
- `GET /api/teacher/sessions/{id}/files/{fileId}/download` — скачать любой файл сессии (bearer).
- `DELETE /api/teacher/sessions/{id}/files/{fileId}` — удалить файл из обмена (bearer).
- `GET /api/taskbooks/{token}` — скачать активный пакет.

Закрытые или истёкшие сессии отдают 404.
